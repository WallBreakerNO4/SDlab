# 进行中评测的预发布与增量快照

> 状态：accepted

评测横跨数天到一周的生成期，中断是预期内的常态；而此前只有完整评测才有发布路径，整段生成期拿不到曝光与搜索引擎收录。决定把「发布」与「完结」解耦：允许把尚未完成的评测发布上线（预发布），网站只维护该评测的最新发布快照；上传时按「计划的单元格是否全部产出」自动判定评测状态（进行中 / 已完结），同一评测的后续快照默认自动取代网站当前快照，仅在快照回退（产出格数变少）时要求显式强制发布。进行中评测照常出现在首页目录、详情页与 sitemap，带「评测中」标记；模型对比只收已完结评测，并在对比页用禁用条目与次要说明告知用户。让「进行中」成为评测的一种状态而不是另立预览实体，是因为评测是网站的基本单位，收藏与对比全部锚在 run_dir / style_key 上，另立身份会让同一次评测产生两套产物与两套收藏锚点。

## Considered Options

- 另立预览实体（独立 run_dir 或独立页面），完结后再发布正式评测：拒绝。同一次评测两套身份与产物，收藏、对比锚点分裂，后续还要合并。
- 等图片全部完成再发布：拒绝。损失整段生成期的曝光与收录窗口，而这是本决策要解决的核心问题。
- 保留手工 `-F/--force-publish` 作为每次补充快照的前提：拒绝。补发是常态而非例外，人工记参数既多余又易错；自动更新 + 回退保护覆盖了它原本的防误意图。
- 由网站实时推导评测状态：拒绝。网站读不到本地生成产物，完整度只能在发布时写入快照。
- 允许进行中评测进入模型对比矩阵：拒绝。矩阵语义是同一画师串的跨模型对比，半列空洞直接伤核心功能；提前曝光由首页与详情页承担。

## Consequences

- 进行中评测的内容会随快照增长；重试只针对失败 / 不完整单元格，已发布图片不会被替换。
- 历史发布快照对象保留在 R2（KB 级），网站只维护最新指针；不做版本历史，也不主动清理。
- 状态与产出格数随发布写入网站数据（首页目录、详情页数据源），网站侧只读。
- 首页排序改为按最近发布时间，生成期间的每次补发都获得曝光位；完结后仍停留前列。
- 单格永久失败的两条出路：`--complete` 手动收口（带缺格完结，缺格在网格中保持占位），或整体删除该评测。
- 上传与生成不并发：由人工在生成暂停点发布，上传端对半写数据做跳过 + 警告。
- 封面图 / 主页缩略图的资产发现移到上传端：上传时扫描 run 目录（以磁盘现状为准），生图侧写入的资产快照不再作为资产来源；生图侧不做改动。
- 两类资产缺失时，首页卡片退化为占位。
