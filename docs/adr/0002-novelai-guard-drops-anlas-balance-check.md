# NovelAI 守卫不再核对 Anlas 余额（移除计费检测）

状态：accepted，部分取代 [ADR 0001](0001-novelai-anlas-guard.md)。

本仓库的 NovelAI API key 为多人拼车共享：其他使用者的消费随时会让账号 Anlas 余额下降，"生成后余额低于基线 = 本次生成被计费"的推断不再成立。误触发时每格都先生成成功、再被判"已计费"标失败（图片被丢弃），整个 run 报废并卡在恢复循环里。因此决定：移除 Anlas 余额基线与生成后余额核对（含余额不可读硬停），守卫只保留两层判定——免费资格参数校验（所有模型）与 V5 生成前电量检查（preflight 与每格生成前）。V5 电量耗尽时由"剩余格子逐格快速失败"升级为真中止：立即停止提交剩余网格单元，已提交单元自然完成，未提交单元保持 incomplete，由人工用 `--retry-incomplete` 恢复。每格订阅查询从两次降为一次。

## Considered Options

- 保留余额核对、放宽触发阈值：拒绝。拼车消费无法与自建消费区分，任何阈值都是猜测，误触发只是时间问题。
- 电量耗尽后剩余格子记为带错误码的失败：拒绝。未提交的格子从未尝试过，标 failed 会制造大量"从未发生成请求"的伪失败记录；incomplete 才是真实状态。
- 电量耗尽后挂起等待回充自动继续：拒绝（与 ADR 0001 同理由），回充以周计，人工恢复语义更可控。

## Consequences

- 守卫不再承诺"杜绝一切 Anlas 扣费"：自身参数与电量守卫仍在，但生成后发生的静默计费不再被检测（这是接受拼车共享 key 的代价）。
- 每格订阅查询减半；"电池剩余"日志改由生成前电量检查打印（preflight 与每格生成前各一次），不再依赖生成后查询。
- 错误码 `anlas_billing_detected` / `anlas_balance_unverifiable` 不再产生；历史 metadata.jsonl 中的记录仍可被 `--retry-error-code` 按原码捞回。
- 电量耗尽导致的中止依赖协调器的 abort 语义：中止前已提交的格子照常成功/失败，只有未提交格子保持 incomplete。
