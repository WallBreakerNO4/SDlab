# ADR-0001：模型使用指南的内容、路由与模型身份

## 状态

Accepted

## 日期

2026-07-23

## 背景

网站需要为模型提供一篇或多篇按语言区分的使用指南。指南用于记录实际使用模型时的经验、推荐方法和已知问题，写作体验应接近普通 Markdown 博客文章，但它不是独立的博客系统。

模型详情页以 `runDir` 作为 URL 参数，指南 frontmatter 以 `model_key` 声明文章归属。当前网站约定模型详情页的路由标识与指南使用的 `model_key` 一致，因此模型页可以直接用已有的 `runDir` 查询构建期指南索引，不需要引入额外的数据映射或发布链路。

指南属于网站内容，由 Git 中的 Markdown 和静态图片构成，并在 Cloudflare 部署构建时编译。它不属于 Python 生图、模型上传、Supabase 数据投影或 R2 发布流程。

## 决策

### 1. 内容契约

模型指南使用仓库内的 Markdown 文件。每个文件的 frontmatter 必须恰好包含以下三个字段：

```yaml
---
model_key: anima-base-1
locale: zh
title: Anima Base 1.0 使用指南
---
```

- `model_key`：文章对应的稳定模型身份。
- `locale`：文章正文的语言，当前只允许 `zh` 或 `en`。
- `title`：文章的显示标题，同时作为页面 H1 和 SEO 标题的内容来源。
- Markdown 正文从二级标题开始；渲染器会将正文中的一级标题降为二级标题，确保页面只有 frontmatter `title` 生成的一个 H1。
- 不允许额外 frontmatter 字段，避免把文章系统逐步扩张成隐式 CMS。
- 文件名和目录只用于组织内容，不承担模型身份或语言身份。
- 同一个 `(model_key, locale)` 最多只能存在一篇文章；重复时构建失败。
- 文章、中文版本和英文版本均为可选。一个模型可以没有指南、只有一个语言版本，或同时拥有两个语言版本。
- 不提供 `draft` 状态。Markdown 文件存在并通过构建校验，即视为已发布；删除文件即撤下该语言版本。

Markdown 正文负责普通文章内容和图片引用。SEO description 复用对应模型的本地化描述；描述缺失时使用站点的本地化固定回退文案，不增加 `description` frontmatter。

### 2. 图片存储

指南图片存放在 `public/model-guides/<model_key>/`，随网站一起部署。Markdown 使用站点根路径引用，例如：

```markdown
![CFG 对比](/model-guides/anima-base-1/cfg-comparison.webp)
```

本功能不增加图片上传、压缩、格式转换或 R2 图床流程。

### 3. 服务端指南索引

构建过程扫描指南 Markdown，校验 frontmatter，并自动生成仅供服务端使用的指南索引。索引按 `model_key` 和 `locale` 查找文章及其元数据。

不维护手工注册表、`run_dir -> model_key` 映射表或文章路径清单。Markdown frontmatter 是文章归属的唯一内容来源，服务端索引只是自动生成的派生数据。

### 4. 公开路由与语言回退

指南的 canonical 路由为：

```text
/[locale]/guides/[modelKey]
```

模型详情页的“使用指南”按钮按以下规则解析：

1. 当前语言存在文章时，导航到当前语言文章。
2. 当前语言不存在、另一语言存在时，导航到另一语言文章。
3. 两种语言都不存在时，不显示按钮。

直接访问指南 URL 时采用相同语义：

- 请求语言存在时渲染文章。
- 请求语言不存在但另一语言存在时，使用临时重定向跳到实际文章语言。
- 两种语言都不存在或 `modelKey` 无效时返回 404。

语言回退使用临时重定向，因为以后新增该语言文章后，原 URL 应恢复为可直接访问的页面，不能被永久重定向缓存锁定。

### 5. 搜索引擎与 sitemap

已发布的指南允许搜索引擎索引。

- sitemap 只列出真实存在的语言文章。
- canonical 指向当前实际渲染文章的 URL。
- `hreflang` 只列出真实存在的语言版本；单语言文章不声明不存在的另一个版本。
- 缺失语言的重定向 URL不进入 sitemap，也不作为 canonical 或 `hreflang` 目标。

### 6. 模型页与指南的关联约定

模型页解析指南的链路固定为：

```text
模型详情页 URL 的 runDir
  -> 构建期 Guide Index 的 model_key
  -> 对应语言的 Markdown 指南
```

具体约束如下：

- 当前 Web 内容契约要求模型详情页 `runDir` 与文章 frontmatter 的 `model_key` 一致。
- 模型详情页直接使用 `runDir` 查询 Guide Index，不额外查询模型元数据。
- 关联失败只表示该模型没有可用指南，页面不显示按钮。
- 本功能不修改 Python 上传器、Supabase schema、R2 对象或模型发布数据。
- 新增或修改指南只需提交 Git，并由网站构建重新生成 Guide Index。

## 备选方案

### 手工维护模型或文章映射表

拒绝。映射表会重复 Markdown frontmatter 和运行数据中的模型身份，形成多个事实来源，增加新增文章、重命名文件和维护语言版本时的不一致风险。

### 为指南增加数据库或上传链路

拒绝。指南由 Git 中的 Markdown 发布，模型详情页已有可用于查找指南的路由标识。为了文章入口新增 Supabase 字段、数据库迁移、Python uploader 写入或 R2 数据，会把静态内容功能错误地耦合到模型发布流程。

### 手工维护 `runDir -> model_key` 映射

拒绝。当前站点约定两者一致，额外映射会制造重复事实来源。若未来明确支持二者不同，应作为独立需求重新设计，而不是提前扩大本功能。

### 缺失语言直接返回 404

拒绝。用户已经确认当前语言缺失时应继续访问另一语言文章；临时重定向让直达 URL 与模型页按钮保持一致。

### 使用 MDX、CMS 或数据库存储文章

拒绝。当前需求只需要 Markdown 写作和仓库内图片。MDX、在线编辑、CMS 权限、草稿发布流和文章数据库都会扩大实现与维护范围。

### 强制中英文成对发布

拒绝。文章本身及每个语言版本都是可选内容，不应因另一语言缺失而阻止发布。

## 后果

- 作者只需新增带三个 frontmatter 字段的 Markdown，并将图片放入 `public`，重新部署网站即可发布。
- 内容变更与撤下需要重新部署网站。
- 模型详情页使用当前 `runDir === model_key` 约定解析文章入口。
- 指南发布与 Python、Supabase、R2 以及模型 release 完全独立。
- 构建阶段会因非法 frontmatter、未知语言或重复 `(model_key, locale)` 失败，从而在部署前阻止含糊内容进入生产环境。
- 指南语言不完整是正常状态；SEO 输出必须基于真实文章集合，而不能沿用固定生成全部站点语言的通用逻辑。

## 不做事项

- 不实现草稿、预览鉴权或发布审批。
- 不实现文章目录页、标签、作者、评论、上一篇/下一篇或相关文章。
- 不实现 CMS、在线编辑、数据库文章正文或远程内容服务。
- 不实现 MDX 组件或文章内交互式控件。
- 不实现图片上传、压缩、转换或 R2 发布工具。
- 不修改生图行为、图片变体、媒体授权或模型 release 语义。
- 不修改或重写现有 R2 view 对象。
- 不为指南新增数据库字段、迁移或 Python 上传逻辑。
